# 記帳介面調整與驗證

## 設計與範圍

桌面（768px 以上）使用單頁雙欄：左側輸入、右側即時分攤預覽。手機使用「支出內容 → 付款與分攤 → 確認帳目」三步流程，底部操作列固定。兩種版型共用原本的表單狀態及提交流程，切換尺寸或返回上一步不清空輸入。

沒有修改 API、DB schema、後端財務規則、應用程式套件或 lockfile。新增時仍預設只有自己參與，不暗中改成全體分攤。多人付款、指定金額、指定＋均分、比例／份數、退款、消費日期、原幣及固定換算匯率均保留。

`expense-preview.mjs` 只負責顯示，不提供提交金額。等分及混合分攤的尾差仍由伺服器隨機分配，預覽顯示可能範圍而非保證特定成員拿到尾差。比例分攤重用既有 `allocateLargestRemainder`；指定金額加總使用 BigInt 檢查。

手機的「繼續」與「儲存」使用不同 React key，且前者取消預設事件，避免按鈕切換成 submit 後，同一次點擊意外送出。文字／數字輸入的 Enter 在前兩步只前進，不直接記帳；輸入法組字時不攔截 Enter。

既有 idempotency key、未確認提交暫存、失敗／結果未知、重試與版本衝突處理不改。預覽在結果未知時明確標示「結果待確認」，不誤稱未儲存。

### 互動情境

桌面即時預覽與單次 POST、手機兩次繼續不得提交、上一步保留內容、Enter 前進、空欄／零參與者阻擋、多付款人加總驗證、指定金額、混合分攤、比例分攤、退款、外幣與手動匯率、尾差範圍、HTTP 400 可編輯、HTTP 503 結果未知、關閉重開後沿用原 key／payload、Tab 焦點限制、Escape 還原捲動。

### 版面情境

320×568、360×640、390×844、430×932、768×1024、1024×768、1440×900、1920×1080，以及 390×480 短視窗。檢查水平溢位、按鈕文字範圍、底部操作列位置、主要按鈕至少 44px 高。另測試 15 位成員、長名稱及跨斷點調整尺寸保留狀態。

測試過程修正了舊樣式造成的手機底部金額逐字換行、段落標題直排、桌面縮窄及選取顏色不一致。截圖與離線瀏覽器重跑腳本另隨交付的 QA 壓縮包提供。

## 尚須部署前驗收

本次未驗證正式 LINE 登入、真實 cookie/session、PostgreSQL 寫入、真實多人同時操作、iOS Safari／Android 實機虛擬鍵盤或既有 DB integration suite。短視窗檢查不等於手機鍵盤實測。外部字型在離線環境使用可用的系統 fallback，實機仍應檢查字型及日期輸入器。

先在預覽／測試環境使用測試帳本完成一次新增、修改、退款與外幣儲存，再合併及部署；不要使用真實帳本做破壞性測試。
